# 手部与扫码交互规格（Hand & Scan）

本文档把「手拿书」与「手持手机扫码」两个新增动作落进现有 scroll 叙事，明确范围、落位、施工顺序、技术参数与回退方案。性能与资产标准沿用 [TDD.md](TDD.md) §4，交付条目补充至 [assets.md](assets.md)。

---

## 1. 范围

**做**

- 右手托握书本（`carry` 携归）
- 手机屏幕显示**实时相机画面**（`binding` 认领），画面中不出现持机的手
- 可选：右手把书放回架上（`return` 传承），复用同一握姿
- 手机道具**不新建**：`ShelfStage.tsx` 的 `PhoneScanner` 已交付程序化机身（92 × 188 × 11 mm）与 Canvas 扫描 UI，本次只升级屏幕画面来源并补后置镜头锚点
- 屏幕 FBO 的首个落点是 00 章已有的扫码窗口（phase 1.66–1.9，扫脊码），不新增编舞即可验证

**不做**

- 手指翻页、掀页、压页。`interaction` 寻址章节仍由现有 ribbon 视觉承担，不加手
- 运行时手指 IK、接触求解
- 真解码二维码。全部状态由 scroll 推导
- 双手、多人
- 预渲染视频/序列帧方案（仅在 §7 作为回退保留）

**核心理由**：两个动作都是**抓握**，物体随手移动，手与物是同一刚体。握姿在 Blender 内一次性贴合，运行时不求解接触，因此「真实接触」不会带来逐帧成本。

## 2. 章节落位

`phase` 数值由 `BookStage.tsx` 现有的 `[data-chapter]` 索引推导，此处用章节内 local progress（0–1）表达，不绑定绝对数值。

| 章节 | 主体 | 手 | 手出现窗口（local） | 说明 |
| --- | --- | --- | --- | --- |
| `arrival` | 书在桌面 | 无 | — | 保持现状 |
| `shelf` | 书在架上 | 无 | — | 已有 `PhoneScanner` 扫脊码；同时是 P0 屏幕 FBO 的验证位 |
| `carry` | 书 | 托握 | 0.00–0.18 进入 / 0.18–0.82 保持 / 0.82–1.00 退出 | 手负责「拿起」，书显式进入可握朝向 |
| `interaction` | 书平摊 | 无 | — | 书落回台面，手离场 |
| `binding` | 书开在 P.042 | 持手机 | 0.00–0.15 进入 / 0.15–0.80 保持 / 0.80–1.00 退出 | 屏幕 FBO 全程只在此时段渲染 |
| `loop` / `read` | — | 无 | — | 保持现状 |
| `return` | 书回架 | 托握（可选） | 倒序复用 `carry` 窗口 | 与 `carry` 形成首尾呼应，增量成本近乎为零 |

**关键结构决策**：两个握持窗口**不重叠**。手一次只握一个物体，因此右手骨架只需两个静态握姿，且不存在多约束互斥问题。

## 3. 施工顺序

按「最容易出彩的先做、最容易翻车的后做」排列。每一阶段独立可交付、可回退。

### P0 · 屏幕 FBO（不依赖手）

以 `ShelfStage.tsx` 中已交付的 `PhoneScanner` 为基线：保留程序化机身与 `drawPhoneScreen` 的取景 UI，在其下方叠一层离屏相机画面，把调色、对焦呼吸、手持抖动、屏幕 bloom 跑通。

验证场位直接用 00 章现成的扫码窗口（phase 1.66–1.9，扫脊码），不需要新编排，也不依赖手。

- 验收：屏幕画面与主场景色温明显不同且可信；无「手机里套手机」；推近构图下二维码可辨
- 回退：静态屏幕贴图，不影响主场景
- **状态：已落地。** 实测桌面 1440×900 与移动 390×844 构图成立，扫码段帧时中位数 16.7 ms（p95 16.8 ms）；`pnpm build` 通过。实现偏差见 §4.10

### P1 · 手资产 + 握姿 + `carry`

接入绑定手模型，在 Blender 内摆 `grip_book`，前端用 socket 刚性跟随，跑通 `carry` 的进入/保持/退出。

- 验收：任意 scroll 位置手与书零穿插；暗调侧逆光下不读作塑料；`carry` 期间书本关键帧已重排为可握朝向
- 回退：`carry` 回退为现有的「悬空书本 + 无手」
- **状态：正式绑定手已落地。** `public/hand/hand.OBJ`（ZBrush 雕刻）由 `scripts/build-hand.py` 重建坐标系并绑定 22 骨骼，2,832 面；双手只在翻开书本时淡入，随封面分开松手，摊平后落到左右两页停留。实现见 §5.6.2

### P2 · `binding` 合成

手 + 手机 + FBO 三者在同一镜头内成立；屏幕内容在 0.80 后从相机画面交叉淡入知识图谱。

- 验收：手机后置镜头位姿与屏幕画面严格一致；屏幕光在手背与内页上有可见照明；进入/退出无跳变
- 回退：P0 的静态屏幕 + 手部特写分镜
- **状态：已在 00 扫码段合成。** 手机随 phase 进入 → 对准封面码 → 锁定 → 释出，屏幕 FBO 与后置镜头在同一镜头内成立；画面中不出现持机的手。`binding` 章节的 P.042 页边码落位与图谱交叉淡入仍未开始。实现说明见 §5.6.1 / §5.6.2

### P3 · 打磨（可选）

`return` 复用握姿、屏幕 selective bloom 调参、移动端降级曲线、`public/fallback` 静态海报。

## 4. 屏幕 FBO 规格

### 4.1 相机

- 镜头锚点：手机背面空物体 `Phone_Lens_Rear`（本地 −0.026, 0.062, −0.0062），只提供视线起点
- **朝向不取自镜头本身**：手机屏幕朝观众，严格按光学推导时后置相机只会拍到空房间。改为沿「镜头 → 页边码」视线，在距标记 0.14 m 处落位并对准标记；距离按镜头到标记距离的 85% 封顶，避免相机穿到书后面
- FOV 32°，near 0.02，far 8
- aspect 等于取景框子矩形宽高比（≈1.09），见 §4.3
- 每帧对 FBO 相机叠加约 0.2°–0.26° 的高频旋转，作为手持抖动；**手机本体不动**

### 4.2 层划分

| 层 | 成员 | FBO 可见 |
| --- | --- | --- |
| `MAIN` | 全部 | 主相机 |
| `CAMERA_VIEW` | 书、桌面、P.042 页边码 | 仅 FBO 相机 |
| `HAND` | 手 | 仅主相机 |
| `PROP` | 手机 | 仅主相机 |
| `SCREEN_BLOOM` | 屏幕发光面 | 仅 bloom 选择层 |

手与手机必须排除出 FBO，否则出现递归。

落地：`src/lib/stage/layers.ts` 定义 `PHONE_CAMERA_LAYER = 1`，`enableLayer()` 对书/桌/书架整棵子树开启；**灯光必须同时加入该层**，否则主体会被渲成全黑。

### 4.3 分辨率策略

- FBO 只覆盖**取景框子矩形**（canvas 坐标 36,170 → 440×404），不是整块屏幕；该矩形在屏面上的实际尺寸约 0.0679 × 0.0623 m，宽高比 ≈ 1.09
- `height = clamp(round(屏幕在视口内的高度 px × dpr × 1.25), 384, 1024)`，`width = round(height × 1.09)`
- 尺寸不是常量：手机在画面里越大越清晰；脚本按主相机投影实测屏幕像素高度，不写死
- 若推镜头后屏幕仍小于视口 22%，优先改构图（让 `binding` 0.45 前后镜头推近），而不是继续提高分辨率

### 4.4 更新频率

- 仅在 `binding` 的可见窗口内渲染，30fps（隔帧）
- 窗口外冻结最后一帧，停止渲染
- 页面不可见（`visibilitychange` / 画布滚出视口）立即停止

### 4.5 色彩管线

- FBO 这趟渲染：`toneMapping = NoToneMapping`，输出 sRGB，避免与主场景 ACES 二次叠加导致发灰
- 屏幕材质用 `MeshBasicMaterial`，不参与主场景光照与 tone mapping
- 屏幕画面单独一级调色：饱和度 −10%，色温 +200K 偏冷，对比 +8%，暗角轻微，静态细噪点约 3%
- 目标不是「还原房间」，而是「一眼看出是手机相机」

### 4.6 对焦与景深

不做真实 DOF（需要额外深度通道与后处理链）。改为屏幕着色器内做中心锐、边缘虚的径向模糊（5 抽头），半径随「对焦呼吸」在 0.6–1.0 之间缓动；`seek` 阶段呼吸幅度加大，`lock` 后收敛。手机拍二维码是微距，这一层是可信度的主要来源。

落地形态：`onBeforeCompile` 注入到屏幕面的 `MeshBasicMaterial`，替换 `<map_fragment>`，因此仍走 three 的色彩空间与 tone mapping 管线。

### 4.7 扫描 UI

- 独立 Canvas 纹理，与相机画面三层叠加（画面 / 取景框与扫光 / 状态提示），UI 层带 alpha
- 状态机 `idle → seek → lock → read`，由 `binding` 的 local progress 驱动，不做真实识别
- `read` 状态后，屏幕内容 crossfade 到知识图谱缩略图（复用 `scripts/build-knowledge-graph.mjs` 产出的 SVG），再与 DOM 侧 `sx-nodes` 的 dispatch 对齐

### 4.8 屏幕照明与 bloom

- emissive 不影响其他物体：补一盏屏幕色弱光（不投影）照亮手背与内页，这是 `binding` 一帧的观感核心
- bloom 用选择性 bloom 只作用于屏幕层：阈值 1.0，强度桌面 0.6 / 移动 0.35
- 落地：P0 **不做 bloom**。全站未引入 `EffectComposer`（`@react-three/postprocessing` 虽在依赖里但未使用），加 composer 会波及整条渲染路径；屏幕亮度暂由既有 additive 光晕平面承担，引入 composer 留到 P3 评估

### 4.9 移动端降级

关闭 FBO，屏幕替换为预渲染静帧 `public/fallback/scan-screen.webp`；扫描 UI 改为静态叠加。判据与现有 reduced-motion / 低功耗判定合并。

落地：未实现。移动端目前直接复用同一路 FBO（390×844 实测帧时正常），静帧兜底随 P3 补。

### 4.10 实现说明

- 屏幕由两层构成：底层相机画面（仅覆盖取景框矩形）+ 上层 Canvas chrome。chrome 必须先铺不透明底、再画文字，否则底色会把状态栏压暗
- 离屏这一趟关闭 tone mapping 并以 sRGB 输出，屏幕面用 `MeshBasicMaterial` + `toneMapped: false`，避免二次 ACES 发灰
- grade 与 5 抽头边缘虚化通过 `onBeforeCompile` 注入屏幕面材质，并设置 `customProgramCacheKey`，防止与其他基础材质共用编译结果
- 首版 grade 过猛（对比 +14%、暗角压到 0.52）导致画面偏红发黑，已收敛为：饱和度 −8%、轻微提亮、阴影偏冷、边缘暗角 0.82、颗粒 0.015

## 5. 手的规格

### 5.1 资产

| 项 | 要求 |
| --- | --- |
| 对象 | 右手，静止放松姿态，正视 +Z |
| 面数 | ≤ 20,000 三角面（含手臂截断）；实交付 2,832 |
| 骨骼 | ≤ 32：腕 + 5 指 × 3–4，无 IK 控制器入 GLB（实交付 22） |
| UV | 无重叠，掌心与指腹贴图密度一致 |
| 单位 | 米，Y 轴向上，导出应用变换 |
| 贴图 | `hand-basecolor` / `hand-normal` / `hand-roughness` / `hand-thickness`，桌面 2048、移动 1024，KTX2 |
| 禁止 | 烘焙进模型的握姿形变、未合并节点、相机灯光残留 |

### 5.2 握姿

- 两个静态握姿：`grip_book`、`grip_phone`，在 Blender 内贴合物体表面，指腹压缩 1–2 mm
- 握姿不作为 GLB 动画片段导出；前端用 socket + 固定偏移刚性附着
- 运行时：`hand.matrix = socket.matrixWorld × gripOffset`，无 IK、无逐帧求解
- `gripWeight` 0–1 在进入/退出窗口内对偏移做位置插值与绕轴旋转插值，保证手滑入而非瞬移
- `gripWeight = 0` 时手位于画外（右下约 0.6 m / −0.5 m / +0.4 m），配合与现有 `.sx-handoff` 同构的明暗衰减做掩护

### 5.3 材质

- `MeshPhysicalMaterial`，底色取源贴图 `hand_map.jpg` 的均值 `#8a5146`（暗部 `#73392e` / 亮部 `#9c5a58`），roughness 0.66，sheen 0.12（暖色），envMapIntensity 0.24，clearcoat 0，不使用 transmission
- 明确接受：three.js 无真实 SSS。方案依赖**低照度 + 侧逆光 + 大量暗部**，漫反射皮肤细节不可见
- 因此手只允许出现在暗调、逆光、局部入画的构图；禁止置于明亮中性光下正面呈现

### 5.4 光照与阴影

- 需要一盏逆光/kicker（沿用 `warm-studio.hdr` 的逆光方向），否则手会读作塑料
- 手开 `receiveShadow`；`castShadow` 桌面端开启，需扩大现有 shadow camera 覆盖范围。当前只有书在桌面投影，加入手后要重调光比
- 移动端关闭手部 `castShadow`，改用烘焙 AO 贴片

### 5.5 预算冲突（需修订 TDD）

[TDD.md](TDD.md) §4.1 现规定场景总面数 ≤ 50,000。手 +20,000 会突破。

- 方案：手控 ≤20,000；书架与桌面做 LOD；总面数上修至 ≤ 70,000
- 需同步更新 `docs/TDD.md` §4.1 与 [assets.md](assets.md) 的对应条目
- 移动端目标：骨骼蒙皮网格 ≤ 2 个（书 + 手），纹理驻留 ≤ 96 MB

### 5.6 手部施工结论

- **握持方向**：把手握成朝下的拳去抓书脊，手臂会横穿书本。可行解是握**下边缘**——手指沿书本宽度展开、掌在封底、手臂向下出画。glTF Y-up 后的手部局部轴：X = 握持轴，−Z = 掌心侧，−Y = 前臂；在书的坐标系里**不旋转**即可得到上述姿态。
- **握持中心必须在原点**：导出前把网格整体平移，让人手围出的那个洞落在世界原点，运行时才能直接挂在 socket 上，不用记魔法偏移。
- **掌心间隙**：握径约 25 mm 内圈对 30 mm 书厚，留 1 mm 余量刚好贴合；再大就会「握空气」。
- **滚动只对 blockout 成立**：旧 blockout 用 `GRIP_ROLL ≈ −0.42 rad` 把前臂甩向镜头；换成平贴封面的扫描手后这个滚角会把掌根埋进封面，运行时已改为不滚（见 §5.6.2）。
- **`carry` 关键帧必须提书**：原来书贴在桌面（0.772），手无处安放。改为抬到 0.945，相机目标同步抬到 0.99。
- **材质必须运行时覆盖**：GLB 自带材质在这套暖棚 HDR 下会读成亮陶土。统一走 `skinMaterial.ts`：底色取贴图均值 `#8a5146`、roughness 0.66、sheen 0.12、envMapIntensity 0.24；`<color_fragment>` 叠两档混合的肤色斑驳（±10%），`<normal_fragment_begin>` 叠毛孔法线，`<opaque_fragment>` 加 0.2 强度的暖色菲涅尔。sheen 超过 0.24 时整只手会读成浅陶土。
- **进场时机**：双手跟随封面的翻开动作淡入（`phase ≈ 2.42`），不再在合上的书封面上停留；`2.86–3.04` 移到左右两页，`3.0–3.72` 停留，之后淡出。

#### 5.6.1 手机（画面中不出现手）

- **持机手已移除**：`PhoneHandRig` 与手机毫米组内的挂载整体删除，扫码段只保留程序化机身、屏幕 FBO 与后置镜头锚点。此前的握姿（绕视线轴滚、肘/腕反向弯折、`PHONE_ANCHOR` 补偿）一并删掉，`hand.glb` 不再被手机段引用。
- **屏幕光保留**：屏幕前的点光仍按扫码透明度驱动，用来给桌面与机身补一点冷光；没有手可打，强度沿用原值即可。
- **两个手部窗口不再冲突**：书本的双手只在翻开时出现（约 phase 2.42 → 3.72），与扫码段完全不重叠。
- **shader 里不能用 `sample`**：GLSL ES 的保留字，ANGLE 直接编译失败，手会整块不可见。`skinMaterial.ts` 中已改为 `skinSamplePos`。

#### 5.6.2 正式绑定手（`public/hand/hand.OBJ`）

- **源雕刻是放松张开的手**：1,102 顶点封闭四边形网格，ZBrush 导出，单位厘米，原始朝向任意。握姿不能靠烘焙——脚本先重建手部坐标系再绑定。
- **坐标系由网格自身量出**：腕端取测地线直径端点 `(−21.40, −36.31, 0)`；`+Y` = 腕→指节中心，`+X` = 小指尖−食指尖（再对 Y 正交化），`+Z = X × Y` = 手背。换算到 glTF Y-up 后 `+Y` = 指尖、`−Z` = 掌心，与旧 blockout 的约定一致。
- **指节位置沿测地线等距取样**：指尖由「距腕测地距离的局部极大」得到五个点；近节 50%、远节 77% 处切分。这样不必猜姿态，弯曲的手指也能贴合。
- **握持中心放在原点**：原点 = 掌面在掌指褶处向掌侧 15 mm（即 30 mm 书厚的一半）。01 携归为**双手**：右手挂 `[+60, −12, 11]`、左手挂 `[−60, −12, 11]`，都**不滚 X 轴**，并整体缩放到 0.75。一张 148 mm 宽的封面放不下两只原尺寸手（掌宽之和已超过书宽），0.75 后两掌落在书两侧、拇指在下缘中间相向。这个外移同样是几何必需的——雕刻的掌面与手指轴线共面，掌面贴合时手指背面会埋进封面约 8 mm。实测该组合下 0 个顶点落在书体积内。
- **前臂与手同网格**：不能另外叠一根套筒——两个壳体在腕口必然留下宽度与法线台阶。做法是在腕关节下方 12 mm 用平面切开残段，丢掉圆头，**直接用切出的边界环做手臂的第一圈顶点**，再向下放样 250 mm（末端 1.35 倍，截面从腕部扁椭圆渐变到接近正圆）。手与臂共享顶点，表面 C0 连续、法线连续，没有接缝；最终网格是一个闭合连通体（0 边界边、0 非流形）。权重由热蒙皮自动分给 `forearm`。
- **不要滚 X 轴**：`GRIP_ROLL = 0`。早期 −0.42 rad 是给 blockout 的抓握臂准备的，套到这张平贴封面的手上会把掌根压进封面，同时把前臂甩向镜头、透视放大。
- **握姿由骨骼摆**：`HandRig.tsx` 里四指用 `BOOK_CURL = [0.03, 0.04, 0.02]`（正向 = 离开掌心；角度压在 ~5°，再大指尖就离开封面悬空），拇指用 `BOOK_THUMB = [0.24, 0, −0.08]` 抬到掌面高度。手机握姿的卷曲另见 §5.6.1。所有角度都乘 `weight` 平滑混入。
- **左右翻开**：两只手各守一边——左手在书脊侧 `x ≈ −72`，右手在书口侧 `x ≈ +72`，掌心落在封面左右边缘，中间留出 40 mm 空档。书的 `openness` 上来后，两只手向各自外侧分开（各 +30 mm），同时略微外旋（`rotation.z = ∓0.32 · spread`），读作把书从左右两边掰开；书自己的页翻机构在中间完成翻开。左手在 `openness 0.30–0.45` 先松、右手在 `0.35–0.55` 再松：两只手同时在场，再错开淡出。外分开的 30 mm 让左手内缘离书脊仍有约 10 mm，封面扫到 65° 前不会穿过它。
- **摊平后不再出手**：双手在 `openness 0.55` 前后松完，`phase 2.75–2.94` 由封面淡出衔接摊平，进入 interaction 段落时页面已经是空手，把注意力留给翻页机构与内页内容。
- **材质必须运行时覆盖**：GLB 自带材质在这套暖棚 HDR 下会读成亮陶土。统一走 `skinMaterial.ts`：底色取贴图均值 `#8a5146`、roughness 0.66、sheen 0.12、envMapIntensity 0.24；`<color_fragment>` 叠两档混合的肤色斑驳（±10%），`<normal_fragment_begin>` 叠毛孔法线，`<opaque_fragment>` 加 0.2 强度的暖色菲涅尔。sheen 超过 0.24 时整只手会读成浅陶土。
